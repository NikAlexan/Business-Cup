# Веб-клиент Resonance — бэклог после подсветки слов

Дата: 2026-11-14. Ветка `feat/web-client`, последний коммит `9769aab`.
Продолжение `2026-11-14-web-client-remaining.md`: раздел 1 (подсветка слов) сделан,
здесь — всё, что осталось, и новая проблема с голосовым профилем.

## 1. Голосовой профиль неинформативен

Пример (baseline, 14 ноября): плитки «Median pitch 88 Hz, range 65–105», «Pace 111 wpm,
167 without pauses», «Pauses 0 %, 0 pauses», «Intonation 9 st»; ниже «What we noticed» и
«Two things to practice».

Проблемы:

- **Числа без смысла.** 88 Hz, 9 st, 111 wpm ничего не говорят человеку: нет ориентира
  (типичный диапазон для чтения вслух, целевой коридор), нет оценки «нормально / стоит
  поработать». Сам отчёт пишет, что высоту тона «нельзя интерпретировать как лучше или хуже» —
  тогда плитка с ней на первом месте только сбивает.
- **Похоже на баг в паузах.** «0 % / 0 pauses» противоречит «111 wpm, 167 без пауз»: разница
  темпов означает ~1/3 времени в паузах. Проверить `app/audio.py` (порог пауз 0.3 с, склейка
  сегментов VAD, на каком отрезке считается `pause_ratio`) на реальной записи.
- **Отчёт общий и не связан с числами.** «Your speech is fairly clear… pacing seems consistent»
  подходит любому. Наблюдения не ссылаются на измерения и конкретные места записи.
- **Технические оговорки на экране.** «No comparable baseline data is available. Pitch
  measurements are given but cannot be directly interpreted…» — служебный текст из
  `report.limitations`, пользователю он не нужен (или нужен человеческим языком).
- **Приоритеты не объяснены.** «Clarity and endings» и «Intonation range» не связаны с
  плитками; коды упражнений `E02 · E03 · E04` — внутренние идентификаторы, а не названия.

Что сделать (обсудить перед реализацией):

- Для каждой метрики — короткая интерпретация и ориентир (например, темп чтения
  ~130–170 wpm; доля пауз 15–25 %; диапазон интонации), с пометкой, где человек
  относительно него. Высоту тона показывать как справку, не как оценку, или убрать из плиток.
- Плитки, относящиеся к приоритетам, выделять и подписывать «работаем над этим».
- Промпт отчёта: требовать опору на измерения и конкретику, запретить общие фразы;
  `limitations` переписать для человека или не показывать.
- Вместо кодов упражнений — их названия.
- Сверить с макетом `design/screens/Profile.html`.

## 2. Подсветка слов — хвосты

- Нет лимита одновременных WebSocket-сессий `/api/v1/speech-follow` (оценка: ~20 потоков
  на ядро). Нужен семафор или отказ с понятным кодом.
- Звук идёт на родной частоте (48 кГц float32, ~190 КБ/с вверх). Для мобильного трафика —
  даунсэмпл в worklet до 16 кГц (×3 меньше) или int16 (×2).
- Живым голосом не проверено — только синтетика `flite` с подменой микрофона. Проверить
  на 2–3 голосах, с акцентом, в шумной комнате; Firefox и Safari (iOS).
- Время слов при воспроизведении сдвинуто примерно на задержку старта второго потока
  микрофона; хвост webm короче потока на ~0.3 с (закрыто показом полного итога на `ended`).
- Подсказка «Words you read turn green» появляется только после открытия сокета — на
  первом дубле её нет до старта записи.

## 3. Сквозной прогон в Chrome

На `localhost:8080`, ширины 390 / 820 / 1280, скриншоты против `design/screens/`:

- новая сессия → запись → анализ → профиль → занятие → перезагрузка на `/exercise/:id`,
  `/done/:id`, `/analyzing` → прогресс → (DEMO_MODE) повторная оценка;
- отказ в микрофоне (MicBlocked), тихая запись (`needs_rerecord`), `failed` анализа с
  причиной и «Try again»;
- запись до лимита — автостоп, запись сохраняется;
- двойной клик по Finish / Complete / Use this take — один запрос;
- 401 без cookie на любой странице кроме `/` → `/`;
- 409 (`lesson_locked`, `plan_item_already_completed`) — текст из `message`;
- PWA: манифест без ошибок, SW активен, в Cache Storage нет `/api`, Lighthouse installable.
  Заметка: обновление SW в режиме `prompt` держит старый бандл до клика в баннере — при
  ручной проверке после пересборки легко смотреть старую версию.

## Паузы: переход на forced alignment (MFA)

`whisper-1` (метки слов для пауз) отключается 26.02.2027, его метки занижают короткие и
теряют длинные паузы. Проба MFA 2026-11-14 на baseline: точнее на длинных паузах
(1.2 с, которую whisper потерял), но образ 7.86 ГБ, пик 2.9 ГБ RAM, холодный запуск
11 с на файл — нужен постоянный процесс в воркере. Проверку текста оставить
(`gpt-transcribe`) + фильтр по `overall_log_likelihood`: при чтении не по тексту MFA даёт
ложные паузы.
