# Интеграция Stripe test mode с веткой улучшений

Выполнена по отдельной команде пользователя после остановки непрерывного цикла. Объединён `origin/main` (`d6b609d`, Stripe PR #8) с `improve/speech-training-loop`, без удаления изменений учебной практики. Новое поручение также разрешает push и PR в main; исходный цикл автоматических улучшений не возобновлялся.

## Совмещённые изменения

- Из main сохранены Stripe test-конфигурация, Checkout, подписанный webhook, Customer Portal, управление/отмена подписки при удалении гостя, paywall/success/canceled/terms и график по времени занятий.
- Сохранены 288 вариантов, свободное завершение дубля, архивная история, восстановление/отмена, reflection с revision, перенос фокуса, приватное A/B и маркировка демоданных.
- Разрешены конфликты `.env.example`, schemas/main/service/demo и клиентских типов/индикатора времени; backend capabilities одновременно содержат оплату и exercise_coaching.
- До оплаты новая запись не запрашивает микрофон даже по прямой ссылке. Сохранённые аудио, заметки и уже созданные A/B доступны после отмены подписки; новые платные действия блокируются сервером.
- SQLite webhook получает блокировку до чтения Guest JSON, согласованную с остальными мутациями и worker. Изменение подписки не должно затирать practice_focus_id; API-регрессия проверяет сохранность фокуса.
- Случайное время демозанятий привязано к каждой местной календарной дате: раннее утро и переход DST больше не сдвигают серию занятий на соседний день. Регрессия фиксирует раннее утро Нью-Йорка.
- График и итоговая статистика одинаково исключают оценочное время нетаймированных подтверждений. Демопопытки помечены prepared_demo; отсутствие реального speech timing не объявляется провалом по темпу. Нулевая практика не отображается как одна минута.
- Автотесты явно используют billing_provider=none для обычных сценариев; Stripe-тесты создают отдельную конфигурацию stripe_test со stub transport. Приватные локальные ключи не изменялись и не публиковались.

## Проверки

- Полный pytest: **224 passed** после исправления демодат.
- Полный Vitest: **108 passed**.
- Полный Chromium E2E: **15 passed**, включая новый путь Stripe test UI.
- После последнего исправления демодат повторены completed-session и Stripe UI journeys: **2 passed**.
- TypeScript/Vite/PWA build, Ruff lint/format по app/tests/migrations/scripts, whitespace checks — pass.
- Все114 JSON response bodies Postman разобраны; конфликтных Git entries нет.

Первый полный backend-прогон выявил только флейк подготовленной серии демозанятий: случайные часы пересекали местную полночь. Это исправлено в генераторе, а тест зафиксирован на раннем утре Нью-Йорка перед повторным полным успешным прогоном.

Backend Stripe fixtures проверяют подпись webhook, порядок событий, выбор тарифа и trial, портал, отмену при удалении, платную запись/фокус, сохранность аудио/A/B после отмены. Browser Stripe-путь использует явно подменённые billing transport и subscription-состояния: он проверяет paywall → checkout redirect → ожидание подтверждения → практика. Реальную страницу Stripe и оплату картой эти проверки не выполняют.

Как в main, BILLING_PROVIDER по умолчанию none. Для включения test mode нужны серверные test credentials и Price IDs; см. [конфигурацию](/home/admin/Business-Cup/design/stripe-test-mode.md). Live mode не поддерживается. Старый [сводный отчёт](/home/admin/Business-Cup/docs/improvements/report-2026-11-15.md) относится к состоянию до этой интеграции.
